# PR B: identidad canónica operativa e históricos

No agrega migraciones ni modifica SQL anterior. Reutiliza alias #608 y maestro físico #613 con aprobaciones de cada empresa. El maestro global FISICA:id tiene representante operativo por empresa: preferir registro propio activo y, en su defecto, accesible. No traslada titularidad ni cambia las FK de históricos. Placa coincidente sin aprobación no consolida nada.

Los catálogos CB2 y disponibilidad Operaciones/TMS ocultan alias y muestran una opción por identidad aprobada. Un ID histórico resuelve al representante para operaciones nuevas; filtros CB2 abarcan los IDs equivalentes bajo empresa del consumo. Reimportar un consumo equivalente no cambia su ID antiguo. Fondos admite equivalencia aprobada sin cambiar línea, categoría, estado ni historial.

La consulta administrativa de históricos inventaría FK directas, columnas convencionales y TMS vía unidad_id. Incluye rutas conocidas de snapshots CB2 y auditoría solo al elegir explícitamente esa fuente, para evitar barridos iniciales; informa las rutas examinadas, sin afirmar interpretación de JSON arbitrario. Cuenta cada fila una vez mediante OR/IN, separa importes por producto/moneda y conserva procedencia empresarial. Fuentes sin empresa directa se señalan para revisión, sin exponer filas. Solo Admin accede al inventario; la pérdida de acceso operativo no borra el historial propio verificable. No sumar referencias de distintas fuentes como abastecimientos.

TMS materializa una unidad mediante resolvedor común en alta, importación, edición y copia/lote. Serializa por empresa, busca placa comparable e identidad antes de insertar, nunca actualiza una unidad TMS histórica y busca el ID en la misma conexión sin confiar en insertId. Un vínculo NULL incompatible requiere revisión: completarlo reinterpretaría planes previos. Las pruebas del orquestador usan un adaptador explícito; el resolvedor real y guardas reales se ejecutan en MariaDB 11.8.9 aislado.

Antes de aplicar código: respaldo nativo privado, SHA-256, restauración de laboratorio, preflight de este PR y postchecks originales de #608/#613. No ejecutar migraciones otra vez. Capturar conteos/importes/IDs/hashes históricos y comparar tras la prueba autorizada. Este PR no consolida pares reales, activa flags ni conecta a producción. Los pares 651/1300 y 684/1301 siguen sujetos a inspección actual y aprobaciones explícitas; los IDs iguales en fixtures son datos sintéticos, no certificación productiva.

Limitaciones para auditoría: el calendario TMS conserva su política actual de intervalos por empresa; este PR no introduce una reserva global entre empresas. La revisión física previa sigue rechazando operaciones abiertas antes de aprobar. Diez fallos preexistentes de la suite amplia se reproducen sin cambios TMS: ocho contratos SQL de cotización, una comparación contra un SHA histórico y un test que requiere unzip no disponible en Windows. No se alteraron esas funcionalidades para ocultarlos.
